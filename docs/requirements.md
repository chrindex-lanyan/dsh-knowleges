# DSH 资料库插件：需求规格

> v0.4 · 纳入最新会话授权、上下文注入和批量操作规则。配套：[技术设计](<design.md>)、[本机试用](<trial.md>)。

## 1. 目标与边界

会话应能在正确的工作区里查阅已生效资料，并主动提交新增、修订、整理和提炼。操作者不必在会话中批准本工作区的读取，但只有在资料库界面明确确认后，单条或一批变更才正式入库。

- **工作区库**：按 DSH 宿主核实的身份隔离。会话无需读审批即可读取正式条目；不接受模型指定其他工作区。无可信归属时不可读取工作区，不自动回退为全局查询。
- **全局库**：一个 DSH 数据域内的共用库。会话读取须单独授权。人工可确认修订标题措辞、标签、置信度和状态；新建全局条目及修订正文、证据、关联，仍由会话基于工作区正式资料提炼、人工审批后入库。
- **操作者**：经 DSH 验证的界面 owner。可选库浏览、授权或撤权、预览和确认、改设置、导出。确认当前提案就构成一次写授权，不需要再进行一轮相同审批。
- **会话**：只获得工具与权限说明，不自动得到库内容；不能给自身授权、批准手头提案、修改管理设置或导出。聊天中的「同意」不代替插件的审核动作。
- 库和待审资料落在 DSH 运行宿主的数据目录，不写入 SSH 工作树、本地镜像或 Git。首版不做跨实例同步、多用户管理、导入、永久删除、无人审批自动整理或跨库批量写入。

## 2. 授权矩阵

| 操作 | 工作区 | 全局 |
| --- | --- | --- |
| 会话搜索、取详情、批量读、整理候选 | 可信绑定后直接读取 | 先获得该 Agent、会话的独立读授权，可选择一次（绑定同一请求）或本会话，可撤销 |
| 会话主动提交新资料 | 允许提交单条或一批草稿，不需先有现存条目或读授权 | 仅可提交基于本工作区已读版本的提炼；更新已存全局条目须先授权读取相应目标版本 |
| 会话修订、标失效、归档 | 基于已读精确版本提出申请 | 基于经授权读取的精确版本提出申请，正文等受提炼规则约束 |
| 提案确认应用 | 对该提案或批次人工确认，只授权这次正式写入 | 对该提案或批次人工确认；全局读授权不等于发布或写权限 |
| 人工查阅历史、管理设置、导出 | 已认证人工界面 | 已认证人工界面 |

全局会话授权不自动继承给其他会话、子代理或另一工作区；撤销或试用停用清除 Host 内授权，已返回到会话中的文本不可撤回。已合法提交的待审草稿仍可处理，但审批须重验绑定、来源和目标版本。

## 3. 功能需求与验收

| 编号 | 要求 | 通过条件 |
| --- | --- | --- |
| R-01 · 双库和权限 | 工作区读免审批；全局读、两库的正式写分别控制。 | 工作区读取无待审批项；冒充作用域、非绑定会话读取失败。未授权全局读不透露存在性、数量或内容。拒绝、过期、冲突无正式版本。 |
| R-02 · 整理 | 人工或会话可提出修订、标失效或归档；恢复由人发起。 | 旧仅是筛选条件，不自动删改；归档在默认搜索隐藏，经人工确认恢复生成新版本。 |
| R-03 · 全局提炼 | 从工作区正式、有效的精确版本提炼，人工批准公开内容。 | 源不可读、已变化或失效时不发布；工作区私有正文、定位和证据不默认公开。 |
| R-04 · SQLite 历史 | 每次实际变更生成不可变快照，最多 N 条旧版本（默认 30），不含当前版。 | 第 33 个版本保留 v33 以及历史 v3–v32；证据、标签、关联与对应版本一致，重复确认不重复写。 |
| R-05 · 字段 | UUID、标题、标签列表、更新时间、置信度、证据列表、关联列表和详情字符串。 | UUID 跨版本稳定，时间由宿主生成，置信度为 0–1 或未评估；列表分表，不用嵌套 JSON 存储。 |
| R-06 · 导出 | 独立导出指定库。 | 单个 SQLite 文件可离线打开，包含正式条目和保留历史；不含其他库、待审、授权或内部来源。 |
| R-07 · 设置与指标 | 在「设置 → 资料库」调整按库历史上限和旧条目阈值，查看指标并可撤销全局读授权。 | 降低 N 须预览裁剪后确认；默认保留 30 条旧版本。显示条目、历史、待审、存储大小与导出指标。 |
| R-08 · 人工界面 | 左侧导航「资料库」能独立于是否打开会话使用。 | 可选库、搜索、看详情/历史，人工编辑/整理先预览再确认，支持审核、下载；窄屏不占用原宿主控件。 |
| R-09 · 上下文注入 | 用 DSH 宿主逐步注入接口，仅给已接入工具的实际 Agent 说明如何调用及权限边界。 | 工具关闭或不可用时无相应提示；注入内容不包含条目、私有路径或凭据；会话可在无需预先对话提示时发现并提交。 |
| R-10 · 批量 | 单次批量读同库最多 20 项。一次提交同库最多 20 个独立目标的新增或维护，按条展示差异后整批授权。 | 审批器只能批准或拒绝整批；任一目标冲突、来源不符或写失败，均无该批正式变更。批量读受返回上限限制时列出待续 UUID。 |

## 4. 实施细则与发布门槛

- **批量边界**：单次一个库，不允许在同一组里重复修改同一个条目。批量新增在工作区，批量全局新增仍走提炼。同一批次可含不同操作；无实际变更的成员不新建版本。
- **审批生命周期**：人可检查发起方、目标库、理由、每项基准/差异和公开范围。未审批的数据不进入搜索和导出；队列跨重启保留，默认 7 天。版本冲突或校验失败不能覆盖当前正式内容。
- **旧与失效**：旧是最近一次变更达到阈值（默认 180 天）；失效是不再适用的显式状态；归档不永久删除，恢复另做新版本。提高历史上限不会找回已裁剪的历史。
- **试用边界**：安装默认没有会话读取，owner 可在设置中明确开启合成数据试用，无需手工调配置。默认安装重启回到关闭。启用前应确认工作区只含合成数据；未验证同账号文件、终端、通用接口和 GUI 能力隔离前，不用于真实或敏感资料。
- **验收**：本地及 SSH 分别验证绑定、会话可用工具、无授权工作区读、全局授权、批量审批以及重绑/冲突；至少用两个工作区，证明其他库不能被间接访问。新版本还应迁移已有 SQLite，不删除正式条目、历史或单条待审草稿。
