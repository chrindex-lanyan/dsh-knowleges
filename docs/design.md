# DSH 资料库插件：技术设计

> v0.4 · 资料库 0.2 设计。配套：[需求规格](<requirements.md>)和[本机试用](<trial.md>)。新增 DSH 会话上下文、工作区读免审批和同库批量授权。

## 1. 可行性与宿主接入

**结论：插件挂载在现有 DSH 上，不另起 Web 服务。** 已在两种环境用同版本真实 DSH 组件挂载并验证最小链路；当前桌面会话的 GUI 启用、真实 SSH 会话、Native/PTC 全链路和通用工具隔离仍须验收。

| 接入点 | 已核对的 DSH 0.2.2-rc.3 契约 | 方案 |
| --- | --- | --- |
| 模型工具与上下文 | `ctx.tools.register(..., { when })` 按真实 Agent 及模型步接纳工具；`ctx.systemPrompt.section` 逐步生成说明。执行上下文含 `exec.agent`、`callId`、`signal`。 | 同一模型步只说明实际已接纳的知识工具；无有效会话、关闭试用或工具被策略排除时不引入说明。服务仍独立检查权限。 |
| UI 入口 | `@deepseek-ai/dsh-client-ui-plugin-manager` 以 `sidebar.panellist.id` 配对 `main.key`。`shell.leading` 是已被宿主使用的单值槽，不是可追加的固定入口。 | 在左栏上部注册「资料库」并用 `ctx.layout.selectPanel` 切换；不替换原导航，不假设主面板持有当前会话。若必须占标题栏最左位置，需要宿主另加扩展位。 |
| 设置 | `@deepseek-ai/dsh-client-ui-settings` 的 root 列表槽 `settings.section` 是应用级设置页。 | 注入「设置 → 资料库」，服务端负责读写及校验设置；不是把配置埋在插件安装页。 |
| 人工审批 | `@deepseek-ai/dsh-user-approval` 的 `ctx.approval.request` 只支持打开的轮次和一次性决定，不能充当跨会话、跨重启的业务审批队列。 | 首版使用插件自己的待审表、差异预览和人工确认。会话工具返回编号和界面提示，不把内置免审批模式当作放行。 |
| Host ↔ Client | `dsh.client` 与 `./client` 供 DSH 加载浏览器工厂；Connection 有已认证的精确 Fetch 路由。 | 同一 npm 包包含 Host 模块与 Client 工厂。人工操作通过现有 Connection 的两个精确路由，重新验证浏览器 Peer；不用单独监听端口或生成 Typert 产物。 |
| 工作区身份 | `@deepseek-ai/dsh-workspace` 的 `WorkspaceId` 是稳定 UUID；`workspaceRegistry` 提供工作区和其校验后的 `sessionIds`。记录被移除后，重新添加同名同路径会得到新 ID。 | 本地用宿主关系验证；SSH 映射需单独验证，不能使用镜像路径推断。 |
| SQLite | DSH 自带的 `@deepseek-ai/dsh-session-query-sqlite` 使用 `node:sqlite`，它自己的库是可重建索引。 | 使用单独的 SQLite 领域库，不借用会话索引或 DSH 的 KV 领域保存条目。 |

## 2. 组件与数据边界

```text
DSH 会话 ── 模型工具（真实 Agent、Session）──┐
                                               │
DSH 资料库面板/设置 ── 人工 RPC（可信 Peer）──→ KnowledgeService
                                               │  授权、提案、提交、导出
                                               ├─ 全局.sqlite
                                               └─ 每工作区一份 SQLite
```

- **Host**：Cordis 服务持有库句柄、作用域解析、迁移、队列、连接和事务。会话工具与人工 API 共用领域校验和提交规则，但没有共用的默认身份；模型适配器不能调用人工确认接口。
- **Client**：仅显示服务器允许的数据与操作。主面板有选库、搜索/筛选、详情和历史、待审核与导出；设置页负责选库配置和指标。打开资料库不切换会话；无法识别当前工作区时由人选择可用库。
- **存储**：按 D3，在 DSH 宿主数据根的专用私有目录下分开保存全局库、每个工作区库和临时产物。路径只由服务用已验证 ID 生成。库有自己的 `library_uuid`、范围和 schema 标识；不向模型返回任何磁盘路径或 SQLite 句柄。Linux 用私有目录/文件权限，Windows 预览沿用宿主数据目录的 ACL。模型启用前仍须配置和验证通用工具、文件系统及桌面隔离。
- **归属**：工作区模式从 `exec.agent.session.id` 解析宿主归属，再按该 ID 找库；不以对话文本、工具传入地址、当前 `cwd`、SSH 别名或镜像路径授权。SSH 对照宿主工作区登记与 `dshRemote.listRemoteProjects()` 的唯一记录，并用工作区 UUID、登记机器 ID、主机、端口、登录名和远程根计算稳定的库身份。不存在可核实记录时拒绝对应工作区调用；重绑或移除再添加不继承库与授权，也不自动删库。
- **全局范围**：同一 DSH 数据域的会话可分别申请读全局；这不等于跨 profile 或设备复制。工作区归属不明确时不回退到全局；明确独立申请全局才走全局授权。

## 3. 权限与操作接口

### 3.1 两类身份，不接受自行声明

1. 会话入口必须持有 DSH 执行上下文。每次先检查插件状态、作用域和读权，再查内容、数量、关联和证据；错误响应不透露未授权对象是否存在。后续关系读取仍要授权。工具不会把资料库内容自动注入系统提示。
2. 人工入口取宿主传入的活跃 Peer，不信任请求字段。实现通过 `ctx.connection.admit(request)` 重新校验浏览器通道，并验证返回的对象正是活跃的 `ctx.connection.browserPeer`。不只看 `principal.kind`：DSH 的程序化连接也可能是 owner。非 owner、非已验证的人机通道及普通模型工具不能授予授权、批准、改设置或导出。其他客户端通道要另外验证后才接入。
3. 待审申请不是授权凭据。确认必须绑定界面展示的提案、目标库、基准版本和内容摘要；服务重查身份、作用域、状态、版本和摘要。截止、取消、拒绝、不可验证及数据异常一律不改正式内容。
4. **上线前必须验证绕过面。** 宿主目录 ACL 只保护 OS 账户边界；同一账号下若模型可读私有目录、启动凭据，能用通用 RPC 或控制审批浏览器，则仅靠按钮或模型工具开关无法实现要求。用宿主能力隔离模型的 shell/文件/PTC/GUI 与凭据；无法实现时，需要独立服务身份与受控通道，不能在该环境用真实数据启用会话访问。

### 3.2 助手如何获取工具和资料

- **上下文注入**：Host 使用 `systemPrompt.section` 注册逐步计算的静态说明，与 step 已接纳的 `knowledge_*` 工具对应。只注入工具名、`scope`、权限和提案规则；不搜索或注入条目、私有路径、凭据，也不向历史插写伪造用户消息。工具因权限、试用关闭或 scope 策略不可用时不提供对应说明。
- **工作区读**：每次由可信 Agent 的 Session 归属推导库。绑定成功即可读取，不产生授权申请；未绑定、角色不明、SSH 端点重绑后均不使用旧库。从工具返回的条目视为数据，不执行其中的指令或链接。
- **全局读**：无授权时在查库前拒绝，创建限时申请。人工允许一次/本会话或拒绝后，原会话重试。一次绑定规范化参数（批量包含有序 UUID），当前会话授权按 Agent 与 Session 隔离。授权、撤权只影响读取；关闭试用会清除内存授权和已读凭据。
- **写授权**：会话主动提交草稿不写正式条目；已通过的提案只授权那个不可变单条或批次的一次应用。全局读不授予发布权限。新全局提炼可在未读取全局库时提交，但修改已有全局条目仍需合法读取基准。

### 3.3 工具和人工接口

| 表面 | 操作 | 限制 |
| --- | --- | --- |
| 会话读取 | `knowledge_search`、`knowledge_get`、`knowledge_get_many`、`knowledge_stale_candidates` | `scope` 仅为 `workspace` 或 `global`。批读同库 1–20 个不同 UUID、不返回私有来源，总量达到约 192 KiB 时返回 `remaining`；不可用项只回请求中的 UUID。 |
| 会话提交 | `knowledge_propose`、`knowledge_propose_batch`、`knowledge_proposal_status` | 批量同库 1–20 项、不同目标，草稿合计最多 224 KiB。改已有条目需先取确切版本；提炼需已读工作区源。仅可查自己的申请状态。 |
| 人工 RPC | 查库、读历史、审批全局读、`stageBatch`/`batchProposals`/`batchProposal`/`decideBatch`、设置、导出 | 宿主解析库；确认绑定不可变摘要；没有绕过审批的写端。`setSessionTools` 仅允许已认证界面明确开启合成数据会话试用。 |

`READ_APPROVAL_REQUIRED`、`ACCESS_DENIED`、`WORKSPACE_UNAVAILABLE`、`PROPOSAL_CONFLICT`、`BUSY_RETRY` 用于明确后续操作。鉴权失败不返回条目数、内容或存在性；不同权限下不改变错误口径。

## 4. SQLite 关系模型

所有库使用同一套 schema。整数时间统一用 UTC epoch 毫秒、展示时转换时区。版本和工作区身份由服务生成；`STRICT`、外键、唯一约束及服务端字段校验互补。

| 表 | 键及主要列 | 约束和用途 |
| --- | --- | --- |
| `library_meta`、`library_settings` | `library_uuid`、`scope`、宿主内库绑定；`max_history`、`stale_after_days`、`settings_revision` | 一文件一库。默认保留 30 条旧版本，默认 180 天提示旧条目。运行配置不导出。 |
| `entry` | `entry_uuid` PK，`current_revision`，`created_at` | UUID 跨版本不变；用可延迟外键指向当前快照。无硬删。 |
| `entry_revision` | PK `(entry_uuid, revision)`；`title`、`detail TEXT`、`confidence REAL`、`status`、`updated_at`、变更种类、操作者类型 | 完整不可变快照；`confidence` 限于 0–1 或 `NULL`；状态 `active` / `invalid` / `archived`。历史按 `revision` 排序，不靠时间戳去重。 |
| `revision_tag` | PK `(entry_uuid, revision, tag_key)`；`label` | 对标签规范化、去重，保留展示文本。标签是无序集合。 |
| `revision_evidence` | PK `(entry_uuid, revision, ordinal)`；`kind`、`label`、`note`、可选 URL 或定型会话/文件定位列 | 有序。文本与引用分列保存，不存嵌套对象；按类型校验。引用默认不展开、不自动访问。 |
| `revision_relation` | PK `(entry_uuid, revision, ordinal)`；`relation_type`、`target_entry_uuid` | 有序；首版普通关联只指同库条目，保留归档目标标记，拒绝自关联。关联不隐含读权。 |
| `revision_source` | PK `(entry_uuid, revision, ordinal)`；`source_library_uuid`、`source_entry_uuid`、`source_revision` | 提炼的内部精确溯源。对所属版本设外键；源是跨文件的逻辑引用，不钉住被裁剪的源历史。 |
| `proposal`、`proposal_revision` 与提案子表 | `proposal_id`、请求幂等键、发起者、类型、目标条目、基准版本、有效期、内容摘要和结构化草稿 | 待审草稿及标签/证据/关联/来源均按列或子表保存；不混在正式版本或导出结果里，也不存整块 JSON。 |
| `proposal_decision`、`settings_audit` | 提案 ID 唯一、结论、确认者、时间、结果版本；配置变更与裁剪计数 | 审计与幂等凭证不依赖版本保留；不能私下保留裁剪后的正文或废提案快照。提案到期或终态清理草稿，只留判定所需元数据。 |

- SQLite schema v1 → v2 为只新增批次、成员关联与审批结果表的事务迁移，不改写原库身份、正式版本或现有单条待审。批量成员复用规范化单条草稿结构；单条读取和确认接口不能访问/批准批量成员。
- 所有版本子表使用复合外键并 `ON DELETE CASCADE`；当前指针受外键保护。历史裁剪不删条目 UUID，也不影响未裁剪版的标签、证据、关联。
- 初版用有界的关键词/标签/状态/时间查询，支持中文子串，语句参数化，模糊匹配符按字面转义；按更新时间及 UUID 稳定分页。按状态/时间、标签规范化键建立索引，压测再决定是否引入全文索引。
- 建议的输入上限：标题 200 字、详情 64 KiB、每条证据及关联各不超过 50 项、标签不超过 30 个。明确的空值、重复、超长及不合法链接在进入提案前验证；字段展现截断不改变所存文本。

## 5. 审批、事务和跨库提炼

### 5.1 审批原子性

1. 会话提交或人工点「预览」时，宿主规范化数据，保存不可变提案与基准版本；返回 `pending` 和 ID。对同一请求的重投去重；改了草稿就是新提案，原确认不能复用。
2. 人查看目标、理由、差异和发布范围，确认时服务以 `BEGIN IMMEDIATE` 重验提案状态/有效期、确认人、摘要与目标当前版本。冲突提示重新生成差异、重新确认；SQLite 正忙时保留待审并允许重试。驳回、过期和冲突不会创建条目版本。
3. 同一目标库事务内插入新版本和子表，原子更新 `current_revision`，裁剪当前版之外最老的版本，登记结论与幂等结果后提交。任一步失败回滚；`approved` 不作为可脱离提交的中间状态。无实际变更记为 `no_change`，不更新条目时间。
4. 成功后重复提交或响应丢失只回原结论，不再执行。判断过期使用服务时钟；模型读租约仅管新读取，已经合法形成的待审稿仍需独立人审；实际工作区解绑或源不可用时不得应用。
5. 归档/标失效/恢复均生成新版本。恢复不倒拨版本号；全局恢复须确认当前内容和来源仍能核验，否则用工作区重新提炼。旧条目清单只是查询，不安排后台自动删改。

### 5.2 同库批量审批

- 暂存时复用单条校验，同时保存有序成员、摘要及幂等标识。各成员可混合新增、更新、标失效、归档、恢复或符合条件的提炼；每个目标最多出现一次。
- 开启目标库写事务，在更新前检查全部目标基准和来源；任何一项冲突，整批标为 `conflict`，无正式写入。运行时 SQL/约束异常回滚全部正式版本及判决，保留待审供重试。No-op 成员不增加版本。确认结果按组且可重复查询，不能按成员单独批准。
- 批量全局提炼/恢复需要锁定来源库时，按稳定标识排序取得只读校验锁，再写唯一目标库，不作跨文件原子提交。

### 5.3 单工作区提炼到全局

1. 会话从自己的工作区读取已批准、有效的源条目。宿主记录针对该 Agent、会话、库、UUID 和版本的短期已读凭据，不把凭据交给模型。提交提案时校验已读记录；工作区读取无人工授权；全局目标一次读授权用完后，可以凭仍有效的已读记录提出草稿，不能凭该记录重读。撤销全局授权会清除对应已读记录。该记录只证明读过这个版本，不证明生成内容忠于来源，仍须人工对比。模型不能用任意路径、对话原文或未批准草稿伪造来源。首版一个提案只用一个工作区，可引用该工作区的多个条目。
2. 待审页面分开显示「将公开的全局内容」和「仅人工核对的来源」。公开内容不自动复制工作区的完整资料、私有证据、路径、文件或会话定位。允许公开的证据须以独立字段显式预览。全局读者不会自动拿到源库访问权、指纹或定位信息。
3. 应用时先按约定锁住来源库（短 `BEGIN IMMEDIATE`，只读校验），再开目标库写事务，检查来源当前版、状态和可信绑定仍匹配，再写全局。只提交目标库、随即释放来源锁；不使用 `ATTACH` 依赖 WAL 多文件原子写。库忙或来源改变时不发全局版本。
4. 全局条目使用自己的 UUID。来源后来变化或被裁剪，显示来源已变化/不可核验；不级联删改已发布版本。人工修改允许的全局展示字段也要审批、留历史，并继承原来源引用；正文、证据和关联由提炼提案修订。

## 6. 设置、导出和运行维护

- **设置**：按库修改 N 和旧条目阈值，服务端校验范围和 `settings_revision`。调低 N 时预览裁剪计数并绑定将裁剪版本集合的摘要；确认时重新核对影响，若不同须重新预览。设置提交与超额历史裁剪同事务，不删除当前版。不修改数据库路径、不建立长期读通行证。会话试用开关默认关闭且不持久化；开启前明确告知工作区读免审批。
- **指标**：各状态条数、历史版本数、库大小（含 WAL/SHM）、当前待审数、审批结果/冲突计数、授权拒绝、裁剪计数、最近导出状态/时间。说明实时计数与宿主启动后累计的口径区别；由已授权人工读取，不记录或上报正文、证据、私有路径。
- **导出**：授权人工选定单库，从 SQLite 只读连接的固定事务快照按列白名单复制到新文件；源继续使用 WAL。导出含库标识、正式条目、版本和三类子表，不含私有来源表、审批/配置/读权或另一库的数据。目标以独立 SQLite 文件交付，写完运行 `integrity_check` 和 `foreign_key_check`，关闭后只带本体试开，不拷贝运行库或输出 WAL/SHM。
- **下载**：使用 Connection 的已认证精确路由和限时、单次的服务端导出凭证，绑定选库与已验证人工通道；不接受路径入参。开始下载前复验权限，识别撤权或取消后停止发送；响应标明附件且不缓存。限额、断线/超时取消和临时文件回收列入验收。已交付字节无法撤回。
- **运维**：启用外键、WAL 与有界忙等待；事务内不等待交互或网络。用 `application_id`、`user_version` 和事务迁移保护升级；如需完整回退点，升级前退出 DSH 并手工备份私有数据目录；遇到不支持的 schema、损坏或磁盘不足应失败并保留原文件，不以空库覆盖。卸载撤销工具、插件 UI 和路由，关闭数据库并清理临时产物，保留库。
